1 · Scenario

Where AiLense starts

  1. A 5-month SOC 2 deadline, Type II.
  2. A 3-hour outage of the self-hosted Keycloak IdP: its SAML signing certificate expired.
  3. Moving to Okta for a managed IdP, HR-driven identity, and attribute-based access.
  4. Okta Verify needs healthy devices, so the fleet moves JumpCloud → Iru first.
  5. The gap assessment runs in parallel, filling time while app owners respond.
  6. Okta and HR-driven lifecycle go live together, with Rippling as the source.

2 · The trigger

An expired certificate, then a rotation that made it worse

Nov 10, 2026. Three hours from detection to resolution, most of it spent getting admins into apps that also signed in through the broken IdP.

  1. 07:00
    Signing certificate expires. No alert.
    Apps that check expiry start rejecting sign-ins.
  2. 07:45
    Detected through help desk tickets.
    Treated as password problems for 25 minutes.
  3. 08:35
    Root cause found.
  4. 08:40
    Key rotated under pressure.
    Every SAML app now fails: each pins the old certificate.
  5. 09:10
    Google restored, bringing back 6 "Sign in with Google" apps.
  6. 09:40
    AWS restored, using an on-call engineer's CLI session that happened to still be valid.
  7. 10:15
    GitHub restored by its only org owner, on PTO, with a recovery code.
  8. 10:35
    Greenhouse restored through vendor support.
  9. 10:45
    Resolved. Two unidentified clients never come back; nobody notices.

What it exposed

  • No owner for the IdP, and no certificate monitoring
  • No inventory of which apps depended on it, or who administered them
  • Admin access ran through the same broken SSO
  • Single admins (GitHub) and an office-bound AWS root MFA key
  • Incident comms ran on Slack, which only worked for existing sessions

Where it leads

Managed IdP, a real app inventory, tested break-glass and admin recovery paths, and certificate alerts that carry over to Okta.

5 · Workstreams

What each one delivers

02

MDM re-enrollment

Prerequisite
  • Four paths, least disruptive first: Apple deadline migration, Iru script via JumpCloud, CrowdStrike RTR, hands-on
  • Keys re-escrowed in Iru; JumpCloud agent kept until health is confirmed
  • Mac and Windows end-user guides; per-device tracker and daily rollup
Migration paths Status snapshot Mac guide
03

Identity / SSO migration

Core project
  • Built in prod (net new, no impact until activation); sandbox backported after launch
  • Groups rebuilt from Rippling attributes; admin groups stay manual with approval
  • Per-app runbook: match NameID, SSO + SCIM, enforce SSO-only, roll back to Keycloak
Plan Tenant & policy Groups App inventory
04

HR-driven lifecycle

Goes live with Okta
  • Rippling creates users up to 4 days early; a pre-start group, excluded from every rule, holds limited access
  • Offboarding runs on Okta deactivation, so a manual deactivation gets the full Google cleanup too
  • Apps without SCIM get a deprovisioning task to their owner

6 · Decisions

The calls, and why

DecisionWhy
Keycloak → OktaWe owned the outage's root cause. A managed IdP removes the single point of failure and adds HR-driven lifecycle and attribute-based access.
SOC 2 scope sets Okta prioritySOC 2 apps first, then existing SSO apps (needed to retire Keycloak), then the rest.
MDM health gates Okta VerifyOkta Verify and device signals need managed, healthy devices.
Build Okta in prodA net-new org has no impact until users activate. Preview orgs run Okta's next release and can mislead.
No separate admin accountsPhishing-resistant MFA, admin console step-up, custom roles, and alerts cover the risk.
Device trust not on day 1SOC 2 doesn't require it. Enforcing it mid-migration would lock out anyone MDM missed.
Google cutover all at onceA per-group cutover confuses users and support; for users it's just a different sign-in check.
Offboarding triggers on deactivationRuns whether Rippling or IT deactivates the user.
Okta Workflows → Slack alerts; SIEM laterFast to stand up. Log retention is handled separately, since Okta keeps only 90 days.
Type II window from mid-JanuaryKeeps the deadline. Controls get stronger during the window, and every change is logged.
